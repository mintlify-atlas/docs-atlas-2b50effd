---
title: "API keys"
description: "Create, list, and delete admin API keys for external integrations."
---

Admin API keys allow external services and integrations to authenticate with the open-attest server. Keys are scoped to an organization and are shown only once at creation time.

All endpoints require the admin secret in the `Authorization` header.

---

## Create API key

<br />

**POST** `/v1/admin/api-keys`

Generates a new API key for an organization. The raw key value is returned once and cannot be retrieved again — store it securely.

### Request

<ParamField path="body.org_id" type="string" required>
  Organization identifier to associate with this key.
</ParamField>

<ParamField path="body.label" type="string">
  Human-readable label for identifying this key (e.g. `"screenata-integration"`).
</ParamField>

### Response

<ResponseField name="api_key" type="string">
  The generated API key. Format: `oak_` followed by 32 hex characters (e.g. `oak_a1b2c3d4...`). Shown only once — save it immediately.
</ResponseField>

<ResponseField name="org_id" type="string">
  The organization ID this key was created for.
</ResponseField>

<ResponseField name="label" type="string | null">
  The label provided at creation, or `null` if none was given.
</ResponseField>

<ResponseField name="note" type="string">
  A reminder message to save the key, since it cannot be retrieved again.
</ResponseField>

### Example

```bash
curl -X POST https://your-worker.workers.dev/v1/admin/api-keys \
  -H "Authorization: Bearer $ADMIN_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"org_id": "acme", "label": "screenata-integration"}'
```

```json
{
  "api_key": "oak_a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4",
  "org_id": "acme",
  "label": "screenata-integration",
  "note": "Save this key — it cannot be retrieved again."
}
```

## List API keys

<br />

**GET** `/v1/admin/api-keys`

Returns metadata for all API keys. Key values are never returned — only hash prefixes are included so you can identify and manage keys.

### Response

<ResponseField name="api_keys" type="object[]">
  Array of API key metadata records.

  <Expandable title="properties">
    <ResponseField name="key_hash_prefix" type="string">
      First 8 characters of the SHA-256 hash of the key, followed by `...` (e.g. `"ab12cd34..."`). Use this to identify a key for deletion.
    </ResponseField>

    <ResponseField name="org_id" type="string">
      Organization this key is scoped to.
    </ResponseField>

    <ResponseField name="label" type="string | null">
      Human-readable label, or `null` if none was set.
    </ResponseField>

    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of when the key was created.
    </ResponseField>
  </Expandable>
</ResponseField>

### Example

```bash
curl https://your-worker.workers.dev/v1/admin/api-keys \
  -H "Authorization: Bearer $ADMIN_SECRET"
```

```json
{
  "api_keys": [
    {
      "key_hash_prefix": "ab12cd34...",
      "org_id": "acme",
      "label": "screenata-integration",
      "created_at": "2026-04-01T10:00:00.000Z"
    }
  ]
}
```

## Delete API key

<br />

**DELETE** `/v1/admin/api-keys`

Permanently deletes an API key identified by its hash prefix. After deletion the key will be rejected on all subsequent requests.

### Request

<ParamField path="body.key_hash_prefix" type="string" required>
  The hash prefix of the key to delete, as returned by the list endpoint (e.g. `"ab12cd34..."`).
</ParamField>

### Response

<ResponseField name="ok" type="boolean">
  `true` when the key was successfully deleted.
</ResponseField>

### Example

```bash
curl -X DELETE https://your-worker.workers.dev/v1/admin/api-keys \
  -H "Authorization: Bearer $ADMIN_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"key_hash_prefix": "ab12cd34..."}'
```

```json
{ "ok": true }
```
